`GET /v1/hosts` 只會列出目前登入者自己的 host，無法自動取得所有 host 的擁有者、CLI／tmux 版本或是否正在跑 leader。因此窗口前必須由每位 host 擁有者主動回報，下表才是升級前與升級後「全數 online」驗收的共同基線。

盤點完成條件：

- 所有已知 host 都有擁有者，且 host 名稱與 UI 中的名稱一致。
- 每台都附 `omnigent --version` 與 `tmux -V` 原始輸出。
- 所有 `tmux` 版本皆為 3.3 以上；不符合者在窗口前完成升級，但不得自行升級 omnigent CLI。
- 所有正在跑 leader 的 host 都已標記，T-1h 可逐台確認停止派工。
- 升級後用同一張表逐台確認重新 online；需手動重啟者記錄原因與處置。

> v0.14 使用行為有以下變更：
>
> - **唯讀分享預設看不到 workspace 檔案。**需要分享檔案時，由 owner 在 Share dialog 明確開啟 **Workspace files**。
> - **Session 自動命名預設開啟。**快捷鍵已調整：`⌘[`／`⌘]`、`⌘⌥S`、`⌘⇧M`；請不要沿用舊版快捷鍵假設。
> - **Codex Auto 模式**的 escalated 請求不再詢問人，會依新版流程繼續；派工前請重新確認 session 的模式與預算。
> - sub-agent 若 **180 秒沒有動靜**，會被判定失敗並喚醒 parent（upstream #5856）；遇到此狀況先查看 parent／child log，不要直接重複派工。
> - ⛔ **現在仍不要自行執行 `omnigent upgrade`。**只有在 WP-2 相容 import 修正已 merge，且 maintainer 明確宣布放行後，host 擁有者才能升 CLI；放行時間會在本串更新。
>
> 請逐台回報「host 名稱＋online／offline」。全部對齊盤點表後才算升級驗收完成。窗口紀錄與驗收證據：<https://github.com/WOOWTECH/Woow_k3s_omnigent_package/issues/3>
