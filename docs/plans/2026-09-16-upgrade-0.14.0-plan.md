# Omnigent 0.14 升級計畫



v0.12.0 → v0.14.0。計畫、分派與驗收由 planner 負責，執行由 recruited agents 與叢集運維承接。每個工作包都有可附證據的驗收條件；未附證據一律視為未完成。

## 結論

  Woow_k3s_omnigent_package 要不要更新要。chart 停在 appVersion 0.11.0、image 浮動 :latest、沒有 startupProbe、host-gc 是死的、PR #1 已被 #2 蓋過。
  升級路徑兩次 helm upgrade：先「釘住 v0.12.0 ＋ 結構加固」（無 migration），維護窗口才換 image 升 v0.14.0。
  bundle 相容（不在 Elmo 的 critical path）.omnigent/ 是 Eugene 的 omnigent 原生 agent team；只在 host CLI 升到 0.13+ 時才斷。WP-2 由 Keel 做完交 Eugene 覆核，WP-3 整包移交 Eugene。
  DB 只能往前v0.12.0 看到新 schema 會 crash-loop。窗口內先 scale 0 再 dump；rollback 只有 A（downgrade）／B（restore）兩條，禁 helm rollback。

範圍（2026-09-16 rev 2）：Elmo 的 critical path ＝ WP-0b → WP-1 → WP-4 runbook → WP-6 A–C（migration／rollback 演練）→ WP-7 → WP-8。.omnigent/ bundle 相關的 WP-3、WP-6 D、WP-8b 與決策 D5／D6 移交 Eugene（bundle 擁有者），不擋窗口；WP-2 已在進行、改動小，由 Keel 完成後交 Eugene 覆核。

為什麼分兩次：把「滾動所有 pod 的結構變更」和「跑 migration」拆開，窗口內的 `helm template` diff 只剩 server image，postgres 不再重啟，rollback 也回到純 image 差異。第一次 upgrade 同時是 `scripts/apply.sh upgrade` 路徑在真 release 上的演練（rev 10 之後還沒 upgrade 過）。

為什麼要 staging 演練 prod 副本：migration 耗時、Rollback A 的 GIN index 重建時間、Rollback B 的 restore 時間，都隨 `conversation_items` 大小線性放大，沒有量測就沒有窗口預估與 go/no-go 門檻。

### 叢集


- namespace `omnigent` 的任何寫入／`exec`／`helm upgrade`，只能由 叢集運維（woow-machines-operator） 執行；paas repo 派出的 agent 只做 `kubectl get`。`dev-sandbox-*` 是 paas agent 可寫的區域。

- 每一次 `scripts/apply.sh` 都帶 `CF_CREDS_JSON=/nonexistent TIMEOUT=30m KUBECONTEXT=woow-k3s`。原因：`apply.sh:79-98` 只要 `/tmp/omnigent-tunnel-creds.json` 存在就會 delete＋create `omnigent-cloudflared-creds`，拿到舊 tunnel 檔會直接讓公開 URL 掛掉。

- ⛔ 禁 `helm rollback`、禁 `--atomic`、禁 `kubectl set image`。migration 開始後這三者都會把 image 退回 v0.12 而 DB 已是 gg → crash-loop；退版一律走 runbook A／B 再用 `apply.sh upgrade --set server.image=…`。

- ⛔ 禁 `helm get values omnigent`（rev 10 的 values 含明文密碼，README 已警告）。

- `helm --wait` 逾時 ≠ 升級失敗：先看 pod 與 log；pod 後來 Ready 而 release 標 failed 時，再跑一次無變更的 `apply.sh upgrade` 修正狀態。

### 證據制

需要 exec／psql／`helm test` 的驗收，由執行者把完整 stdout（含指令、時間戳、`--context`）貼進追蹤 issue；驗收 agent 只核對附件齊全與數值。缺附件＝FAIL。
